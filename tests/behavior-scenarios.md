# Scenariusze zachowania - 1.5.1

1. Fotograf solo: Q01 -> potwierdzenie modułu photography -> pytania foto; brak pytań o saksofonistę, perkusistę i DJ-owskie atrakcje.
2. Firma filmowa z kilkoma operatorami: jedna usługa video, skład zapisany jako sposób realizacji, a nie osobne usługi.
3. Filmowiec/kamerzysta: synonimy nie tworzą automatycznie dwóch modułów; niejasność wymaga krótkiego potwierdzenia.
4. Muzyk lub zespół: music; pytania o skład, sety i rozszerzenia muzyczne, bez albumów fotograficznych.
5. Foto-video: photography + video; wspólne dane firmy i styl tylko raz.
6. Firma kompleksowa DJ + muzycy + foto + video: kilka modułów; własne usługi, podwykonawcy i tylko polecani partnerzy są rozróżnione.
7. Nietypowa usługa: universal; logiczne pola scope, delivery_team, extras, related_services bez improwizowania nowej metodologii.
8. PDF/DOCX: dane uzupełniają profil, ale cena podstawowa nie staje się stałą ceną przyszłych ofert.
9. Stary mail: dane Pary, rabat, cena, dojazd i termin nie trafiają do profilu; można zaproponować abstrakcyjne reguły stylu.
10. WWW i PDF są sprzeczne: pokaż konflikt i poproś o rozstrzygnięcie, nie wybieraj sam źródła.
11. Instagram/Facebook: link można zapisać, ale brak automatycznej analizy jako źródła oferty.
12. Firma foto-video, Para pyta tylko o zdjęcia: mail używa photography i nie dopisuje filmu.
13. Firma kompleksowa, Para kupuje wspólny pakiet: jedna oferta może obejmować kilka usług, a podanej ceny pakietu nie sumuje się drugi raz z katalogów.
14. Demo: scenariusz odpowiada głównej usłudze albo combined; dane demo nie trafiają do profilu.
15. Migracja z wcześniejszej wersji: zachowaj profil i styl, potwierdź mapę usług i dopytaj wyłącznie o nowe braki.
16. Aktualizacja 1.5.1: manifest obejmuje wszystkie zarządzane pliki wydania, ale nie profile klienta; instalacja nadal wymaga zgody.

Automatyczne testy plików i helperów nie dowodzą działania konkretnej aplikacji desktopowej ani dostępu do lokalnego folderu klienta.
